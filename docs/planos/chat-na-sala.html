Chat na sala

Texto curto na sala, sem interromper quem fala: um link, um “entro já”, o que assistir. Entrega pelo socket de sinalização que já existe; o servidor só retransmite, como faz com peerState. Nada de media passa por ele, nada é gravado, nada sobrevive à saída da sala.

Decisões: broadcast para a sala inteira · painel aberto por botão no dock · histórico só em memória · strings em pt-BR · nenhuma dependência nova.

1 · Protocolo — src/shared/protocol.ts

Um verbo chat nos dois sentidos. Sem bump de PROTOCOL_VERSION: clientes antigos ignoram verbos desconhecidos e servidores antigos descartam o novo.

export interface ChatPayload {
  from: PeerId
  clientId: string  // estável entre reconnects; marca mensagens "minhas"
  name: string
  hue: number
  text: string
  at: number
}
  • ClientMessage: | { t: 'chat'; text: string }
  • ServerMessage: | ({ t: 'chat' } & ChatPayload)

Autor, nome e cor vão no payload porque o servidor os conhece (não vêm do cliente) e porque sobrevivem a quem sai ou reconecta com outro id. O servidor devolve a mensagem também a quem enviou: um caminho só, sem insert otimista nem dedupe.

2 · Servidores — os dois

  • server/src/index.ts: case 'chat' no switch (~linha 252). Validar typeof msg.text === 'string', trim + slice(0, 500), descartar vazio. broadcast(room, ...) para todos com peer.info e Date.now().
  • worker/src/room.ts: mesmo caso (~linha 300), com self.info e this.broadcast({...}). Sem storage, sem report(), sem alarme — chat não muda o censo da sala. Cada mensagem custa um request faturado, o mesmo custo de peerState.

3 · Sessão — src/renderer/src/rtc/mesh-session.ts

  • const CHAT_LIMIT = 200; campo private readonly chat: ChatEntry[] = [].
  • SessionSnapshot ganha chat: ChatEntry[]; buildSnapshot() → chat: [...this.chat].
  • handle() ganha case 'chat': mine: message.clientId === this.clientId, push, shift() acima de 200, emit(). Sem som.
  • disconnect(): this.chat.length = 0 junto com peers.clear(). connect() chama disconnect(): trocar de sala limpa; um blip de sinalização não limpa — é a mesma sessão.
  • Método público sendChat(text): faz trim e chama this.signaling?.send({ t: 'chat', text: trimmed }).

Signaling.send() já descarta mensagens com o socket fechado. Aceitar best-effort; não construir fila offline.

6 · Verificação

  1. npm run typecheck, npm --prefix server run typecheck, npm --prefix worker run typecheck.
  2. npm run signal + npm run dev + npm run peer: duas janelas, mesma sala, nomes diferentes. Mensagem aparece nas duas, inclusive para quem enviou. Espaços não enviam; texto longo chega com no máximo 500 caracteres.
  3. Fechar/reabrir por clique fora e Escape; digitar no chat não aciona atalhos (f, m, setas).
  4. Sair e entrar: histórico vazio. Reiniciar o servidor com as janelas abertas: histórico permanece após o reconnect.
  5. Com o Worker local: npm --prefix worker run dev, apontar MIRANTE_SIGNAL_URL para ele e repetir o item 2.
